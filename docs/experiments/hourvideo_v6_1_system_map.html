HourVideo V6.1：当前系统结构图

这张图描述的是当前 coarse-locked shared investigation 线路；V3 保持独立、不受这里的改动影响。

一句话：先用地图把整道题的相关范围锁出来，做一次共享调查；调查得到的事实必须经过关键事实核验，随后 mapping 只能使用留下的事实判断全部选项，final 再决定是确认还是诚实猜测。

主链路

输入

questionA–E options
Coarse / Medium / Fine map

R1 是结构地图；R3 有 caption / ASR 语义地图。

→

1. Planner

仍按选项提出检索计划，分别判断哪些 Coarse 区域相关。

输出：每个选项的 Coarse locks、检索 query、排除理由。
→

2. Shared investigation

把所有选项锁定的 Coarse 取并集，整道题只做一次调查循环：地图 → recheck → Fine 图片 → 更新调查。

输出：atomic_facts、每条事实的 evidence IDs、调查状态。
→

3. Fact verification gate

只挑会影响选项区分的关键事实，回查其引用的 caption / ASR。

verified 保留
unverified 从 mapping 输入移除

可信事实集

保留原始调查记录供审计；另生成只含可用事实的列表。

→

4. Option mapping

只能看可信 atomic facts，不能看完整证据池、也不能重读原始长叙事。

每个 A–E 都必须输出：

supportedrefutedunresolved
used_facts
支持或否定一个选项时，必须报出实际使用了哪几条 facts。
→

5. Final gate

从 mapping 的 used_facts 正向汇总 citations。

confirmed 唯一 supported 且有引用
budget_exhausted_guess 多候选、未解决或预算耗尽
→

输出

答案、final status、实际引用、caveat，以及共享调查与核验记录。

刚加上的两道“信息边界”

A. 不可信事实不能进入答案层

以前

核验失败的事实仍可能出现在长总结里；mapping 看到了它，AI 可能继续使用。

现在

核验失败的 fact 根本不传给 mapping。例如 messy room → Bedroom 被拒绝后，mapping 看不到 Bedroom。

→
B. 引用只从实际依据生成

以前

final 可能把 shared investigation 的整包 evidence IDs 都带上。

现在

每个选项先报告 used_facts；final 只引用这些 facts 自己的 evidence IDs。

→
结果

防止两种绕路

1. 不可信总结一路传到答案；
2. 同一证据既支持可信事实、又被误当成支持脑补事实时被“一刀切”删除。

Plaster 题揭出的剩余缺口

不是 “Bedroom” 那类完全无根据的词，而是目标对象被偷换

原始证据：F037 shows spraying water into the bucket/compound.
错误 atomic fact：The camera wearer dampened the wall surface ...

两个句子都含有 “spraying water”，现有语义核验因此可能误放行；但关键对象是 bucket/compound，不是 wall surface。

当前未完全解决 这说明 shared investigation 仍可能把事实向选项措辞靠拢，而 fact verifier 对“动作发生在什么对象上”的核验还不够严格。

下一步对应的结构改动：discriminator checklist。先抽出 A/B 真正不同的点（这里是“是否弄湿墙面”），再让共享调查单独回答这个小问题，而不是从长总结中间接推断。

谁负责什么？

组件当前责任不负责什么
Planner按选项锁定可能相关的 Coarse 区域，提出检索词。不直接决定选项真假。
Shared investigation / SFC对整道题调查一次，结合地图、文字与必要 Fine 图片产出带引用的 facts。不应在没有证据时把模糊描述具体化。
Fact verification检查关键事实是否真的被它自己的引用文本支持。当前还不能完全识别复杂的对象/目标偷换。
Mapping把可信 facts 映射成每个选项的 supported / refuted / unresolved。不能自行查原始 evidence、不能发明新事实。
Final gate仅在唯一支持且有证据链时标 confirmed；否则标猜测及 caveat。不能把“结构上唯一”误称为“视频理解一定正确”。

当前仍未解决的三层问题

1. 关键区分点

尚未有 discriminator checklist。共享调查仍可能没有正面核对选项真正不同的那一句。

2. 证据理解

时长边界、细粒度动作、以及 “bucket ≠ wall” 这类目标关系仍会出错。

3. 成本与索引

Planner 仍为五个选项产生重复计划；跨轮 hash 缓存、抽帧与 indexer 暂未调整。

状态：V6.1 fact-verified mapping checkpoint。此图说明系统结构与已知边界，不把单次十题准确率视为统计结论。
